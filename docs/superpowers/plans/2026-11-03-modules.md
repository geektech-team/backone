# Business Modules Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans with independent parallel tasks. Track steps with checkboxes.

**Goal:** Add standard @Module and feature-local organization to framework, scaffolds, demo and docs.
**Architecture:** Explicit instances and registration; selector metadata reads instance members at registration; whole graph preflight shares existing HTTP/WS validation before commit.
**Tech Stack:** Bun, strict TypeScript, standard decorators, no runtime dependencies.
**Spec:** docs/superpowers/specs/2026-11-03-modules-design.md

## Global Constraints

- Preserve dirty changes, versions, functional API and direct Controller/Gateway registration.
- Bun >=1.3.10, TypeScript >=5.2; no reflection DI or scanning.
- Application owns resources; Module groups explicit objects, no implicit lifecycle.
- Work in current checkout; do not commit or publish.

## Review Focus

- Entire batch preflight across HTTP and WS; no partial routes or module registry.
- Import cycles, diamond sharing, same instance at different prefixes.
- Capture prefixes without changing server.prefix; preserve parameter/cache namespaces.
- Require own metadata and execute selectors at most once per new module.
- Generated and demo routes/lifecycle survive file moves.
